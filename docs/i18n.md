# 다국어

| 하는 일                    | 위치                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| 지원 언어 목록 · 기본 언어 | `src/i18n/locales.ts` (ko · en · zh · ja · es, 기본 ko)          |
| 요청마다 언어 고르기       | `src/i18n/request.ts`                                            |
| 문구                       | `messages/<언어>.json`                                           |
| 키 타입 검사               | `src/i18n/global.ts`                                             |
| 키 · 인자 일치 테스트      | `src/i18n/messages.test.ts`                                      |
| 권역 · 도시 · 장소 이름표  | `src/features/names` (만드는 스크립트 `scripts/build-names.mjs`) |
| 데이터 번역 표(앱 번역)    | `src/features/translations` (아래 「데이터 번역」)               |

- 언어는 URL이 아니라 `locale` 쿠키로 정한다. 쿠키가 없거나 목록에 없는 값이면 기본 언어를 쓴다
- 언어 바꾸기: 공통 UI `LocaleSwitch`(언어 메뉴)가 서버 함수 `setLocale`(`src/i18n/actions.ts`)을 부른다.
  서버 함수에서 쿠키를 바꾸면 Next.js가 지금 화면을 새 언어로 다시 그린다
- 문구는 화면 단위로 묶는다: `{ "Home": { "title": "..." } }`
- 꺼내 쓰는 법
  - 서버 컴포넌트: `useTranslations("Home")`, async 함수 안에서는 `await getTranslations("Home")`
  - 클라이언트 컴포넌트: `useTranslations("Home")`
- 키는 `ko.json`을 기준으로 타입 검사된다. 새 키는 `ko.json`에 넣고 **5개 파일 모두**에 같은 키를 넣는다
- 언어를 추가하려면 `locales`에 코드를 넣고 `messages/<코드>.json`을 만든다. 메뉴의 언어 이름은 `LOCALE_NAMES`(그 언어로 쓴 이름)

## 5개 언어

한국어 · English · 中文(简体) · 日本語 · Español. 팀장 PoC(`Tour-Navigator-App`)와 같은 5개다.

### 키 일치 테스트 (`src/i18n/messages.test.ts`)

`npm run test`가 5개 파일을 비교한다. 하나라도 어긋나면 실패한다.

- 키 구조가 `ko.json`과 같다(빠진 키 · 남는 키 없음), 빈 문구 없음
- ICU 인자(`{name}` · `{count, plural, …}`의 이름) 집합이 `ko.json` 또는 `en.json`과 같다.
  언어마다 쓰는 인자가 다른 문구가 있어서다(날짜 `{month}` · `{monthName}`, 한국어뿐인 출처 이름 `{source}`는 외국어 화면에서 뺀다)
- 복수형 갈래: 중 · 일은 `other`만(복수형이 없어 대개 한국어처럼 `{count}`를 그대로 쓴다), 영어 · 스페인어는 `one` · `other`
- 한국어가 아닌 파일에 한글이 없다(영어 파일에도 한글이 있는 문구만 예외)

### 번역 원칙

- UI 말투는 짧고 자연스럽게(직역하지 않는다). 스페인어는 길어지기 쉬워 버튼 · 칩 · 탭은 영어만큼 짧게
- 브랜드 · 작품명은 원어 그대로: Tour Navigator, RESCENE, K-Drama, KTX, SRT, YouTube 등
- 자리표시자 `{x}`는 그대로 둔다
- 중국어는 간체와 중국어 문장부호(，。：“”), 일본어는 일본어 문장부호(、。「」)
- 같은 개념은 PoC 번역을 따른다: `Tour Planner.dc.html`의 `REG`(권역) · `CATS` · `I18N`(분류 · 도시), `Tour Navigator Home.dc.html`과 테마 화면의 `TX_DICT`
- 한국 지명 · 기관명은 공식 외국어 표기(PoC · 한국관광공사 표기)가 있으면 그것을 쓴다
- 원본 데이터가 한국어뿐인 것(장소 이름 · 설명 · 운영시간 · 좌표 기준, 시티투어, 관광안내소, 장면 제목)은 앱이 만든 번역 표로 옮기고(아래 「데이터 번역」),
  그 화면에 「앱이 번역했어요」 안내 한 줄을 둔다. 외국어 화면에 한국어 원문을 보이지 않는다
- 테마 포스터는 한국어 · 영어만 있다. 중 · 일 · 스페인어 화면은 영어 포스터(`posterPath`, `features/recommend/works.ts`)
- 데이터 파일에 딸린 짧은 문구(테마 여행 정보의 축제 · 링크 이름, 플래너 안내 링크)는 `data/info.ts`에 5개 언어로 둔다(PoC `TX_DICT` 값)

## 작품명 · 데이터 문구

- 작품 · 채널 이름(테마 장소 데이터의 `work`, 「왕과 사는 남자 (2026)」)은 `features/theme/work-titles.ts`의 `workTitle`로 옮긴다.
  표는 PoC `TX_DICT_TITLES`(테마 · 홈 · 플래너 파일의 표를 합친 것)이고, 이름만 바꾸고 연도 표기는 그대로 둔다. 그 언어 값이 없으면 영어.
  긴 이름부터 바꾼다(PoC는 「공식 유튜브」가 먼저라 「국가유산청 공식 유튜브」가 반쯤만 바뀐다). 영화 탭 카드 · 장소 시트 「작품」 행 · 지도 시트의 장면 한 줄에 쓴다
- 장면 제목(`sceneTitle` · 장면 짧은 제목 · RESCENE 영상 제목)은 원천이 한국어뿐이라 앱 번역 표(`translations/data/scenes.en.json`)로 옮기고,
  영화 탭 제목 아래에 외국어 화면에만 안내 한 줄(`Theme.film.translatedNote`)을 둔다. 작품명이면 `workTitle`(공식 제목)이 먼저다
- 숫자 · 단위가 섞인 한국어 정형 문구(운영 · 휴무 · 요금)는 4개 언어 번역 표(`translations/data/phrases.json`)가 먼저이고,
  표에 없으면 `lib/kr-units.ts`의 `krUnits`(PoC `KR_UNIT` · `krUnits`, 규칙 순서 그대로)로 바꾼다

## 데이터 이름 (권역 · 도시 · 장소)

장소 이름처럼 데이터에 딸린 번역은 문구 파일에 넣지 않는다. 한국어 · 영어는 데이터(`ko` · `en` 필드)에 있고,
중 · 일 · 스페인어는 언어별 이름표 `src/features/names/data/<언어>.json`(`{ regions, cities, places }`)에 있다.

| 이름 | 원천 (PoC)                                                          |
| ---- | ------------------------------------------------------------------- |
| 권역 | `Tour Planner.dc.html` `REG`의 zh · ja · es                         |
| 도시 | `CITY_NAME`의 zh · ja · es, 없으면 `I18N.locs`(zh · ja)             |
| 장소 | `파생 데이터/장소.csv`의 `장소명(중문)` · `장소명(일문)`(공식 명칭) |

- **떨어짐 규칙**: 그 언어 공식 명칭 → 앱이 옮긴 그 언어 이름(아래 「데이터 번역」 `place-names.<언어>.json`) → 영어 → 한국어.
  한국어 화면은 늘 한국어. 플래너 빌드 장소(같은 장소 통합 뒤 3,049곳)는 중 · 일 · 스페인어 모두 공식 명칭이나 앱이 옮긴 이름이 있다
  (중문 공식 791 + 앱 2,258, 일문 공식 908 + 앱 2,141, 스페인어 앱 3,049. 합쳐 뺀 장소의 공식 명칭은 남긴 장소로 옮겼다). `loadNameTable`이 공식 명칭을 앞에 두고 합친다
- 신규 관광지(`kto:`, 홈 인기 관광지)는 한국관광공사 다국어 관광정보(영 · 중 · 일 · 스페인어)에서 좌표로 찾은 공식 이름을 장소에 싣고(`names` · `en`),
  영문 이름이 없으면 앱이 로마자(`lib/romanize.ts`, 국어의 로마자 표기법 기본 규칙)로 옮긴다. `docs/api.md` 「신규 관광지」
- 꺼내 쓰는 법: `placeName(place, locale, names)` · `cityName(city, locale, names)` · `regionName(region, locale, names)`
  - 서버 컴포넌트: `const names = await loadNameTable(locale)` (`features/names/server.ts`)
  - 클라이언트 컴포넌트: `const names = useNameTable()` (`features/names/NamesProvider.tsx`)
- 이름표는 그 언어 화면일 때만 싣는다. 루트 레이아웃이 서버에서 그 언어의 표 하나만 불러와 `NamesProvider`로 내려 주고,
  다른 언어 표는 클라이언트 번들에 들어가지 않는다. 한국어 · 영어는 빈 표
- 역 · 터미널 같은 관문 이름과 장소 설명은 한국어 · 영어만 있어 중 · 일 · 스페인어 화면은 영어를 쓴다
- 원천에 영어 이름이 없던 플래너 장소(1,254곳)는 앱이 만든 영어 이름으로 채워져 있다(아래 「데이터 번역」).
  중 · 일 이름표에 한글이 섞인 값(원천 입력 실수)과 그 장소가 아닌 값(좌표로 붙은 근처 가게 · 안에 든 시설 · 두 곳 묶음, 예: 명동대성당 → 피부과,
  창경궁 → 홍화문, 궁남지 → 서동공원과 궁남지. `scripts/official-name-fixes.mjs` `WRONG_OFFICIAL_NAMES`, 일문 22 · 중문 19곳)은 공식 명칭으로 쓰지 않는다
  (`build-names.mjs` · `build-planner.mjs`가 거르고, 그 장소는 앱이 옮긴 이름을 쓴다. 2026-10-01 일본어 장소명 점검)
- 이름표를 다시 만들 때: `node scripts/build-names.mjs <Tour Planner.dc.html> <파생 데이터 폴더>` → `npm run format`

## 글꼴 · 형식

- Pretendard에는 한자 · 가나가 없어 중 · 일 글자는 시스템 CJK 글꼴로 그린다(`globals.css` `--font-stack`).
  `<html lang>`이 화면 언어를 따르고, `:lang(zh)` · `:lang(ja)`에서 그 언어 글꼴을 한국어 글꼴보다 앞에 둔다(한국어 글꼴의 한자 모양이 섞이지 않게)
- `break-keep`(단어 단위 줄바꿈)은 한국어 · 영어 · 스페인어만. 중 · 일은 띄어쓰기가 없어 기본 줄바꿈을 쓴다(`app/layout.tsx`)
- 날짜 · 숫자 · 시간은 `Intl`(`DateTimeFormat` · `NumberFormat`)에 화면 언어를 넘겨 그 언어 형식으로 쓴다

## 데이터 번역 (앱 번역, 비공식)

외국어(en · zh · ja · es) 화면에 보이는 글자(문구 · `aria-label` · `title` · `alt` 포함)에 한글이 없게 한다(2026-09-28 대표 요청).
원천 데이터가 한국어뿐인 값은 **앱(개발 중 Claude)이 직접 만든 번역 표**로 옮긴다. 외부 번역 API는 쓰지 않았고, 공식 번역이 아니다.
그래서 화면에 「앱이 번역했어요」 안내를 둔다(장소 시트 `PlaceSheet.appTranslated` · 영화 탭 `Theme.film.translatedNote` ·
시티투어 `Home.citytour.dataNote` · `Planner.info.citytour.source` · 관광안내소 `Planner.info.tic.source`).

| 표 (`src/features/translations/data/`) | 내용                                                                                                | 언어               |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------ |
| `place-names.en.json`                  | 원천에 영어 이름이 없던 플래너 장소 id → 영어 이름 (1,253)                                          | 영어               |
| `place-names.zh.json` · `ja` · `es`    | 그 언어 공식 명칭이 없는 플래너 장소 id → 이름 (중 2,258 · 일 2,141 · 스페인어 3,049)               | 중 · 일 · 스페인어 |
| `names.en.json`                        | 고유명사 한국어 → 영어: 설명 틀 속 장소 · 시티투어 노선 · 정류장 · 탑승지 · 관광안내소 이름 (2,718) | 영어               |
| `categories.en.json`                   | 설명 틀의 분류 이름 (135)                                                                           | 영어               |
| `phrases.json`                         | 운영시간 · 요금 · 휴무 같은 짧은 정형 문구 (661)                                                    | 4개 언어           |
| `addresses.en.json`                    | 관광안내소 주소 → 영문 주소(번지 · 도로 · 읍면동 · 시군구 · 시도 순) (571)                          | 영어               |
| `sources.json`                         | 좌표 기준의 출처 종류(카카오 좌표 · 연관 관광지 · 시티투어 경유지 · Google geocoding 등)            | 4개 언어           |
| `scenes.en.json`                       | 장면 제목 · RESCENE 영상 제목                                                                       | 영어               |

- 번역 원칙: 원문에 없는 정보를 더하지 않는다. 숫자 · 시각 · 전화번호 · 금액은 그대로(천 · 만 단위는 숫자로 풀어 쓴다).
  고유명사는 국어의 로마자 표기법 + 한국관광공사 영문 표기 관례(해수욕장 Beach, 사찰 「Bulguksa Temple」, 캠핑장 Campground,
  브랜드 · 호텔은 그 브랜드의 영문 표기). 장소 이름은 중 · 일 · 스페인어도 만든다(2026-09-29 대표 요청): 중 · 일은 한자어 고유명사를
  확실한 한자로(경복궁 → 景福宫 · 景福宮), 순우리말 · 불확실한 이름은 중문은 영어 로마자 그대로 · 일문은 가타카나로 두고 일반 명사(해수욕장 · 시장 · 공원 · 카페)만 옮긴다.
  스페인어는 영어 이름의 로마자 고유명사를 그대로 두고 일반 명사만 옮긴다(Haeundae Beach → Playa de Haeundae).
  나머지 긴 데이터(설명 · 정류장 · 주소)는 영어만 만들고 중 · 일 · 스페인어는 공식 명칭이 없으면 영어,
  짧은 정형 문구는 4개 언어
- 쓰는 곳: 장소 영어 이름은 `scripts/place-names.mjs`가 플래너 `places.json`의 `en`에 채운다(`build-planner.mjs`가 부른다).
  나머지는 조회 함수 `src/features/translations/text.ts`(`phraseText` · `placeDescEn` · `sourceText` · `sceneText` · `cityTourText` · `infoCenterText`)가 쓴다.
  표가 무거워 **서버에서만** 부른다: 플래너 장소 시트는 Route Handler(`/api/planner/places/[id]?locale=`)가 옮긴 설명 · 운영시간 · 좌표 기준(`view`)을 돌려주고,
  테마 · 홈 · 여행 정보 탭은 서버 컴포넌트가 옮긴 글을 props로 넘긴다. 클라이언트 컴포넌트가 표에 닿지 않는지는 `translations/bundle.test.ts`
- 좌표 기준: 출처 종류만 옮기고 한국어 주소 조각은 외국어 화면에서 뺀다(위도 · 경도 · 카카오맵 줄이 따로 있다). 남는 것이 없으면 줄을 숨긴다
- 갱신: 원천이 바뀌어 한글이 새로 생기면 `npm run test`의 `translations/text.test.ts`(언어별 한글 0건 · 숫자 열 일치)가 실패한다.
  빠진 값을 표에 더하고(같은 원칙으로), 장소 이름을 고쳤으면 `node scripts/place-names.mjs` → `npm run format`
- 예외(한글을 그대로 둔다): 언어 메뉴의 「한국어」(자기 언어로 쓴 언어 이름). 카카오 지도 바탕 지도의 지명(지도 이미지라 글자가 아니다, 카카오 지도는 영문 지도가 없다)
- 카카오 지도 SDK 문구: 확대 · 축소는 SDK `ZoomControl` 대신 우리 버튼(`Common.map.zoomIn` · `zoomOut`), 로고는 지우지 않고 대체 글만 `Common.map.kakaoLogo`로 바꾼다
- 점검: 단위 테스트(`translations/text.test.ts`)와 브라우저 점검 `scripts/check-hangul.mjs`(dev 서버를 띄운 뒤 실행, 사용법은 파일 머리 주석.
  언어별 · 페이지별 한글 건수 · 가로 넘침 · 콘솔 오류를 출력한다. CI에는 넣지 않는다)
